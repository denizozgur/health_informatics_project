# fMRI EDA: checking and exploring the preprocessed resting-state fMRI

This step comes before any brain features are built from the LEMON resting-state fMRI. It answers four questions:

- What is in the download?
- Does it match the documentation?
- Is the signal sensible?
- Can we trust it?

**Read next:**
- [overview.ipynb](overview.ipynb): every check, the verification and all figures in one notebook.
- [FINDINGS.md](FINDINGS.md): the results for 159 scans, with every failed check explained.
- [COLAB.md](COLAB.md): how to run the heavy step on Google Colab.

## How it works

1. **`scripts/check_fmri.py`: inventory.** Which of the 228 participants have a scan in the public archive, and the file sizes.
2. **`scripts/eda_extract.py`: the heavy step.** It reads each 2.2 GB scan once and saves a ~22 MB summary per person to `data/derived/fmri_eda/eda/cache/`. It takes about 50 s per scan and 7 GB of RAM. It can be resumed, and `--workers N` runs N scans at once. The same code runs on Colab through `colab/fmri_extract_colab.ipynb`, which is generated by `scripts/build_colab_notebook.py`.
3. **`scripts/eda_report.py`: checks, tables and figures.** It reads the summaries and evaluates 43 checks. Each check is a claim with an ID (A1, B2, ...), a method, the measured value and a status:
   - PASS: the data meet the stated expectation;
   - FAIL: they do not;
   - INFO: a measurement with no pass/fail rule.

   It takes about 4 minutes for 159 people.
4. **`scripts/eda_verify.py`: independent re-check.** Separate code recomputes key numbers from the raw files: header bytes, voxel statistics, scanner triggers and motion. It also checks that a scan processed on the laptop and on Colab gives identical results.

Run them from the project root:

```bash
uv run python analysis/fmri_eda/scripts/check_fmri.py
```

```bash
uv run python analysis/fmri_eda/scripts/eda_extract.py --workers 1
```

```bash
uv run python analysis/fmri_eda/scripts/eda_report.py
```

```bash
uv run python analysis/fmri_eda/scripts/eda_verify.py --all
```

**Inputs**, all under `data/LEMON/` and only ever read:
- `MRI_MNI2mm/*_MNI2mm.nii.gz`: the preprocessed scans;
- `MRI_extras/confounds/`: motion and noise regressors, one file per person;
- `MRI_extras/bold_json/`: raw-scan sidecars, used for the TR;
- `MRI_extras/qc_pdf/`: the pipeline's QC reports (10 people);
- `name_match.csv` and `Participants_LEMON.csv`: ID mapping, age and sex.

The QC step needs `pdftotext` (poppler-utils).

## How to read the figures

In all figures, red = older (55-80) and blue = younger (20-40).

- **fig01 Timing.** The gap between scanner triggers, the TR in the raw sidecars, and the TR in the header. The header is the odd one out: it says 1.0 s, but the true value is 1.4 s.
- **fig02 Values.** Histogram of brain values on a log scale against a bell curve, and voxel std (target 1). This shows the data are z-scored.
- **fig03 Voxel std histogram.** A spike of near-empty padding and a hump of brain. The dashed line is the 0.4 cut-off.
- **fig04 Brain maps.** The share of people with brain at each location, and the mean variability.
- **fig05 Power spectrum.** How fast the signal fluctuates (Hz). The dashed curve is the pipeline's band-pass filter; the spectrum follows it.
- **fig10 Spatial structure.** Correlation falls with distance. Left-right mirror pairs correlate more than control pairs, as in real brain signal.
- **fig11 Connectivity.**
  - Left: the group connectivity matrix.
  - Middle: each person's first-half vs second-half similarity. The bright diagonal means each person matches themself.
  - Right: connectivity against distance.
- **fig12 Age groups.** One dot per person; the bar is the group mean.

## Terms

| Term | Meaning |
|---|---|
| voxel / volume | A 2 mm cube of brain, and one full 3D image. Each scan has 652 volumes, one every 1.4 s (the **TR**) |
| MNI space | The standard brain template everyone is warped to, so a voxel is the same place in every person |
| z-scored | Each voxel's time series has mean 0 and std 1 |
| band-pass filter | Keeps slow fluctuations (about 0.01-0.1 Hz) and removes drift and fast noise |
| confounds | Motion, noise components (aCompCor) and trends, regressed out of the signal by the pipeline |
| MeanFD | Average head movement between frames, in mm |
| DVARS / global signal | Frame-to-frame change of the whole image / brain-average signal |
| functional connectivity (FC) | Correlation between the time series of two regions. Here the regions are 10 mm cubes, a placeholder until an atlas is chosen |
| split-half reliability / fingerprinting | FC from the first vs the second half of a scan, and whether that identifies the person |
| Dice | Overlap of two masks (1 = identical) |
| permutation test | A p-value from reshuffling the older/younger labels many times |

Statements about how the pipeline worked cite its public code: [NeuroanatomyAndConnectivity/pipelines `src/lsd_lemon`](https://github.com/NeuroanatomyAndConnectivity/pipelines/tree/master/src/lsd_lemon), commit `9904065`.
